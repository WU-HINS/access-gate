## 二、本轮已落地（四方评估的共识项）

### 2.1 门禁：从「人工白名单」改为「派生规则」★

**三家独立指出的同一处**（架构师 #4 / 实现者 #9 / 红队 #9）：

> 人工维护的白名单是**缺陷之源**——实测 **40 张表中 14 张不在任何白名单**，且刚补进白名单的两张表**声明仍不满足谓词**。

**已改为从表声明派生**（02 §1）：

| 规则 | 内容 |
|---|---|
| **R1** | 若表有 siteId → 必须 notNull；若有唯一键，其首列必须是 siteId |
| **R2** | 若表无 siteId 但有 ownerScope → 必须 ownerScope + ownerId 双非空 |
| **R3** | 若两者皆无 → 必须在**平台级表豁免清单**中且逐表给出理由 |
| **R4** | 违反 R1/R2 或未在 R3 豁免 → db:check **启动失败** |
| **R5** | **双作用域表**（有 scope 判别列）可豁免 notNull，但须有 CHECK 保证「scope 与哪个 id 非空」一致 |

### 2.2 四张违规表已修正
