> ## ⚠️ 更新（本会话核实）：**数字已变，语义未变**
>
> | 本文写 | 实测 |
> |---|---|
> | CI **12 项** | **13 项** —— 新增 **第 13 项「架构验收 M4-17：宿主无知」**（删除 `src/plugin/builtin/` 后核心仍可编译，证明核心不依赖任何具体插件） |

> **目的**：让「**声称达成**」与「**每次都被验证**」的对应关系一眼可见——
> ★ 包括**未被 CI 覆盖**的那两项，以及它们的复跑方式。

> ★ 起因（R84 的审计）：R81 证明「**不默认跑的检查会骗人**」。

## 二、★ 目标要求 ↔ CI 覆盖（**核心矩阵**）

| 目标要求 | 覆盖它的 CI 项 | 状态 |
|---|---|---|
| **(1)** 真实 PG 模式启动 + 完整主线（登录 → 两级选择 → 控制台导航 → 资格查询） | **10**（`serve-real-e2e.ts` 19 步）+ **2**（29 个真实 PG 单测） | ✅ **默认覆盖** |
| **(2)** 容器化真跑（`docker build` + `compose up` + 卷持久化） | ❌ **无** | ⚠️ **环境无 Docker**（见 §三） |
| **(3)** 真实 IdP 两条链路隔离（真实授权码流程） | **10**（`serve-real-e2e.ts` 的 ⑤-8a~e：stub IdP **真实 RSA 签名** + 真实验签 + 隔离断言） | ✅ **默认覆盖** |
| **(4)** 性能（管理读 ≥500 QPS · p99 有界 · **10 万主体**） | **12**（`bench.ts --assert`） | ✅ **默认覆盖** |
| **(5)** 长跑稳定（巡检 + 定时任务，无泄漏/无累积错误） | ❌ **无**（仅 **10** 覆盖了「巡检存活」这一**子集**） | ⚠️ **需人工复跑**（见 §三） |
| **(6)** 报告 + `npm run ci` 全绿 + `npm test` 0 跳过 | **2**（含 skip 门禁）+ 全部 12 项 | ✅ **默认覆盖** |

★★ **读这张表的方式**：
- ✅ **默认覆盖** = 每次 `npm run ci` 都会验证；**没人需要记得跑**；
- ⚠️ = **仍然依赖「有人记得跑」**——★ 这正是本矩阵要暴露的东西。

## 三、★ 未被 CI 覆盖的两项（如实列出）

### (2) 容器化真跑 —— 环境无 Docker

| 已有 | 内容 |
|---|---|
| `tools/docker-preflight.ts` | **静态检查 11/11**（Dockerfile / compose / 健康检查 / 优雅停止 / 卷 / **部署一致性**：`serve.ts` 必需的环境变量都出现在 `docker-compose.yml`） |
| ★ 5 项**显式标注「无法在本环境验证」** | 真实 `build` / `up` / 健康检查 / 优雅停 / **容器重建后数据仍在** |
| `reports/containerization-runbook.md` | **183 行可执行 Runbook**（含 `down` 不带 `-v` → 重建 → 数据仍在；以及 `down -v` 的反向证明） |

★ **本环境无法验证**（未安装 Docker / daemon 不可用 / 无 podman）。
★★ **不声称达成**——静态检查**不能替代**真实执行。

### (5) 长跑稳定 —— 证据已归档，但需人工复跑

| 已有 | 内容 |
|---|---|
| `tools/soak.ts` | 采样：子进程 RSS · PG 进程数 · `/metrics` 错误计数 · **巡检 `run_count`/`fail_count`** |
| **25 分钟实测**（R89） | 50 QPS · **71952 请求 0 失败** · 巡检 **48 次递增** · `fail_count` **全程 0** · ★ **RSS 后半段 11 分钟仅涨 0.2MB**（146.8→147.0）· 均延迟稳定 23.5ms |
| 完整时间序列 | `reports/M0-acceptance.md` §134 |

★ **复跑方式**：
```bash
node --experimental-strip-types tools/soak.ts --minutes=25 --interval=60 --load=50
```

★★ **为什么没进 CI**：25 分钟会让 CI 从 ~5 分钟变成 ~30 分钟。
★★★ **诚实结论**：它**仍依赖「有人记得跑」**——与性能项修好之前的状态相同。
★ 而且**它仍不是小时级**：12 分钟能证明「无快速泄漏」（每秒几十 KB 也看得出来），
但**不能证明「无缓慢泄漏」**（如每天增长几 MB）。

## 四、本矩阵自身的维护约定

1. ★ **新增能力时，问一句**：「它会被哪一项 CI 覆盖？」——
   若答案是「没有」，那就**要么补一项，要么在 §三 里如实登记**；
2. ★ **`AG_CI_SKIP_*` 的跳过必须记为 WARN**（不能是 PASS）——
   「跳过 ≠ 通过」是本项目的纪律；
3. ★ **每项检查都要有 `--self-test`**（或等价的反例验证）——
   「检查通过」的前提是「检查**不恒真**」（`path-probe` / `route-coverage` / `authz-coverage` 已有）；
4. ★ **检查必须能看到「原因」**，而不只是「计数」——
   R60 让 `skipped` **计数**可见，R77 才让 `skipped` 的**原因**可见。
