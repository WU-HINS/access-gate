## 0. 一句话定位

**access-gate** 是一个**基于插件的通用信任引擎**：
用插件采集信任证据 → 用嵌套表达式判定信任等级 → 用动作插件把结果投射到下游系统。

核心只认识四个抽象：**Subject 主体 / Fact 证据 / Policy 策略 / Grant 授予**。
核心代码中不得出现任何具体系统名（如 new-api）——这是**可机械检查的硬约束**（grep = 0）。
首个接入方是 new-api，但它**不是**架构前提。

## 5. 第一步做什么（最重要）

**写一个 0.5 人日的 spike**：让 `02-数据模型.md` 的 Schema 声明**真跑一次 DDL 到空库**。

为什么这是第一步：

1. 它能**机器化暴露**所有归属缺陷（人工白名单已经证实会漏）
2. `02` 里已经发现过两处**无法生成 DDL** 的损坏（`defaultSql` 生成 `DEFAULT {}`、行尾字面量换行符）
3. 它是三家评估共同给出的「**只改一处**」建议——**修的是产生缺陷的机制**

**通过标准**：空库能建出全部表；`db:check` 对故意制造的漂移报错；派生规则（`02 §1` 的 R1–R5）能拦住违规表。

## 6. 已知的坑（血泪经验，务必看）

### 6.1 批量脚本比逐个精确编辑更容易静默出错

本项目文档里曾出现 **110 处 `' + BT + '` 残文**——批量脚本的转义错误，**它们不报错、只污染内容**。

**建议**：改文档用 `edit` 工具（精确匹配）或**按行号替换**；批量 `sed`/正则只用于**可验证的**简单替换（如改名），且改完必须 grep 复核。

### 6.2 「已修复」必须回到承载文档核对

本项目出现过**三次声称已修但根本没落地**（`baseline` 在 `02` 中 0 次、`restore` 0 次、`敏感` 0 次）。

**建议**：每次说「已修」，都在承载文档里 `grep` 一次出现次数。

### 6.3 人工维护的白名单是缺陷之源

实测 **40 张表中 14 张不在任何白名单**，且刚补进白名单的表**声明仍不满足谓词**。

**已改为派生规则**（`02 §1` 的 R1–R5）——新表只要声明了 `siteId` 就自动被约束，不需要人记得更新清单。

### 6.4 引用要回到原文，不要引用摘要

四场辩论中双方都在「引用摘要而非原文」，导致多起事实错误（如「三代 SRE-4」在文档中根本不存在）。

**建议**：任何论断引用章节号后，`grep` 回原文核对。

### 6.5 「做减法」时必须同步删除下游引用

第 9 代砍掉了 process 运行时 / UI 贡献宿主 / feature kind，但这些**仍被场景 A 的流程引用**。

**教训**：删机制时要连带清理它的**依赖方**，否则实现时会发现「规格悬空」。
